# agent-skills

Third-party lifecycle pack (complementary; eval technique + hook evidence + positioning).

**Adopted (2026-07-11 triage)**
- **Deterministic trigger/collision check on skill descriptions.** agent-skills' Tier-2 eval is free and CI-safe: stemmed TF-IDF over all descriptions; pinned *positive* prompts (realistic user asks, paraphrased — never copied from the description) must rank their skill top-k; *negative* prompts declare an `owner` skill that must outrank this one (a pairwise routing test that can't pass vacuously); pairwise description similarity ≥75% errors. koan adopted "description as trigger surface" from ponytail but had **no check that the six trigger surfaces route or don't collide** — wrap/readback/lint share vocabulary ("session", "docs", "handoff"), and a description reword tripped nothing (the canary pins rule phrases, not routing). D-016 caution applied: pocket version, not the framework. · agent-skills evals/README.md + scripts/run-evals.js · _adopted_ → `benchmarks/triggers.mjs` + `triggers.json` (12 pinned prompts, rank-1 strict, collision ≥75% errors), wired into selfcheck check 4 + `bench:selftest`. Calibration found the pocket ranker's own FP class: a *function word* landing in a single description becomes a fake discriminator ("them" → koan-init, "with" → koan-wrap) — fixed with a function-word stoplist; the mis-owned-prompt and identical-description bad refs are pinned in `--selftest` (D-014 discipline).
- **The D-020/D-024 hook deferral's premise was stricter than field practice.** agent-skills ships a working `SessionStart` hook as a **Claude plugin**: `hooks.json` resolving via `${CLAUDE_PLUGIN_ROOT}` with a `${CLAUDE_PROJECT_DIR}` fallback, degrading gracefully (`|| true`; INFO message when `jq` is missing). Notably it does NOT solve cross-target hooks — hooks exist for Claude only; the other 8 tools go without, and nobody treats that as broken. koan deferred SessionStart (D-020) and PreCompact (D-024) on "per-target plumbing that doesn't exist yet for non-Claude targets" — evidence the parity framing was the wrong gate: a claude-plugin build target could ship both hooks Claude-only, today. The target itself stays unbuilt (D-013/D-020 scope discipline). · agent-skills hooks/hooks.json + .claude-plugin/ · _adopted_ → D-020/D-024 **Revisit if** lines re-scoped from "a hook-capable build target arrives" to "we choose to build a claude-plugin target."
