# rtk

First **mechanical complement**, not a rival methodology — a Rust token-proxy
(`rtk-ai/rtk`, v0.28.2, Apache-2.0) that composes *below* koan in the stack
rather than overlapping its axis. Every prior ingest was another take on
build-less or lose-less *discipline*; RTK operates one layer down, at the
tool-output surface, and the synergy is orthogonality, not a borrowed rule.

**Proposed (triage — awaiting a D-entry)**
- **Orthogonal token economy — RTK and koan cut non-overlapping token classes, and RTK's savings feed D-024's thesis.** RTK is a `PreToolUse:Bash` hook (`rtk hook`) that rewrites `git status`/`cargo test`/`grep`/… into compact-output equivalents (claimed 60–90%; a 30-min Claude Code session table: ~118k→~24k tokens). koan cuts *authored/derived* tokens (over-building; re-derivation across sessions); RTK cuts *tool-output* tokens *within* a session. They compose with zero overlap — different layers of the same context-exhaustion problem. The composition is not neutral: less tool-output burn ⇒ later/less `/compact` ⇒ fewer lossy-summary events, which is exactly the loss D-024's checkpoint clause exists to catch. RTK is a *mechanical* way to buy the context budget koan's discipline tries to *preserve*. First ingest where the right output is a positioning note (companion in the stack), not a rule to adopt. · rtk README savings table + `.claude/hooks/rtk-rewrite.sh` (exit-code protocol: 0 allow / 1 passthrough / 2 native-deny / 3 ask) · _proposed_ → README/D-007 positioning line; optionally one template "companion tools" pointer (free channel per D-019 — a pointer, never koan-managed machinery).
- **The wrap-vs-truncation caveat — a genuine LOSE-LESS interaction to document before recommending RTK.** RTK truncates/rewrites `git log`/`git diff`/`git status`. Two koan rituals read git — but through different tool channels, and only one is exposed. koan-lint reads DECISIONS/HANDOFF via **file reads** (`Read`/`Grep`), and RTK's hook *explicitly* skips those ("the hook only runs on Bash tool calls; `Read`, `Grep`, `Glob` do not pass through") — so the deterministic lint is safe. But **koan-wrap summarizes the session from git via Bash**, so `rtk git log`/`rtk git diff` could hand wrap *compressed* input and yield a lossier HANDOFF — a subtle lose-less regression from an otherwise pro-context tool. The caveat, not a blocker: if koan ever names RTK as a companion, state that wrap/lint should see raw git (or that RTK's compaction is faithful enough for a handoff summary). The caveat is itself the shippable lesson — the exact class of "the token-saver quietly starved the continuity ritual" koan is built to notice. · rtk README ("hook only runs on Bash… not auto-rewritten") vs koan-wrap step reading git · _proposed_ → one caveat line wherever RTK is documented; no src change until the companion pointer lands.
